🧱 The Four Pillars of OOP Core

🔒 Encapsulation
Binding data + methods, hiding internal state.
private getters/setters
📦 Abstraction
Hiding implementation, showing only interface.
pure virtual abstract classes
🧬 Inheritance
Creating new classes from existing ones.
class Derived : public Base
🎭 Polymorphism
Same interface, different behaviors.
virtual functions overloading
💡 Real‑world analogies: Encapsulation → medicine capsule (hide contents); Abstraction → TV remote (only buttons); Inheritance → child inherits from parent; Polymorphism → “Start” button works differently for car / bike.

📐 Classes & Objects

Class – blueprint for creating objects (attributes + methods).
Object – instance of a class, with its own state and behavior.

class Car {
        public:
            string brand, model;
            Car(string b, string m) : brand(b), model(m) {}
            void start() { cout << brand << " " << model << " engine started."; }
        };
        Car myCar("Toyota", "Camry");
        myCar.start();
✔ Constructor – special method to initialize objects. Called automatically at creation.
✔ Destructor – releases resources when object goes out of scope. Can be virtual.

🧬 Inheritance Code Reuse

Derived class inherits properties & behavior from base class. Promotes hierarchy and reuse.

Types of Inheritance

  • Single – one base, one derived
  • Multiple – derived from two or more base classes
  • Multilevel – chain of inheritance (A → B → C)
  • Hierarchical – multiple derived from one base
  • Hybrid – combination of multiple + multilevel
⚠ Diamond Problem: When a class inherits from two classes that both inherit from the same base. Solved using virtual inheritance (virtual keyword on base class in intermediate classes). 
class A { public: void show() { cout << "A"; } };
        class B : virtual public A { };
        class C : virtual public A { };
        class D : public B, public C { };   // only one copy of A

🎭 Polymorphism Runtime & Compile‑time

Compile‑time (Early Binding)

  • Function overloading – same name, different parameters
  • Operator overloading – define behavior for user‑defined types

Runtime (Late Binding)

  • Function overriding – derived class redefines a virtual function from base
  • Resolved at runtime using vtable (virtual table) and vptr (virtual pointer)
class Animal {
        public:
            virtual void sound() { cout << "Animal sound"; }
        };
        class Dog : public Animal {
        public:
            void sound() override { cout << "Woof"; }
        };
        Animal* ptr = new Dog();
        ptr->sound();   // "Woof" (runtime polymorphism)

🧩 Virtual Functions & Abstract Classes

  • Virtual function – defined in base, can be overridden in derived. Enables runtime polymorphism.
  • Pure virtual function – virtual void func() = 0; → makes class abstract.
  • Abstract class – cannot be instantiated; must be subclassed.
  • Virtual destructor – required when deleting through base pointer to ensure derived destructor runs.
class Base {
        public:
            virtual void show() = 0;        // pure virtual → abstract
            virtual ~Base() { }             // virtual destructor
        };
        class Derived : public Base {
        public:
            void show() override { cout << "Derived"; }
        };
⚠ Constructors cannot be virtual. Static functions cannot be virtual.

⭐ SOLID Principles Best Practices

  • S – Single Responsibility: each class has one reason to change.
  • O – Open/Closed: open for extension, closed for modification.
  • L – Liskov Substitution: subtypes must be substitutable for base types.
  • I – Interface Segregation: don't force clients to depend on unused interfaces.
  • D – Dependency Inversion: depend on abstractions, not concretions.
✔ Favor composition over inheritance – more flexible and modular.

🧩 Design Patterns Creational · Structural · Behavioral

  • Creational: Singleton, Factory, Abstract Factory, Builder, Prototype
  • Structural: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy
  • Behavioral: Observer, Strategy, Command, Template, Iterator, State, Chain of Responsibility
💡 Singleton – restricts a class to a single instance.
💡 Factory – defines an interface for creating objects, lets subclasses decide which class to instantiate.

📐 OOAD Object‑Oriented Analysis & Design

Systematic approach using OOP principles. Phases:

  1. Requirement Analysis – understand stakeholder needs
  2. System Design – architecture, components, interfaces
  3. Object‑Oriented Modeling – UML diagrams (class, sequence, state, etc.)
  4. Implementation – code based on design
  5. Testing – unit, integration, system
  6. Deployment – production & maintenance

⚠️ Exception Handling

  • try – code that may throw
  • catch – handles specific exception types
  • throw – signals an exception
  • finally – cleanup code (runs always)
try {
            int result = num1 / num2;
        } catch (const std::exception& e) {
            cout << "Error: " << e.what();
        }

🧠 Memory Layout (C++ Object)

  • Data members – stored in order (padding may apply)
  • vptr – virtual pointer (8 bytes on 64‑bit) if class has virtual functions
  • Size of empty class – 1 byte (ensures unique addresses)
✔ vtable – array of function pointers, shared per class.
✔ vptr – each object points to its class's vtable.

🎯 Top Interview Questions Must Know

  • Q: Why OOP?
    A: Code reusability, data security, flexibility, easier maintenance.
  • Q: Difference between struct and class?
    A: Struct members are public by default; class members are private.
  • Q: What is a virtual destructor?
    A: Ensures derived destructor runs when deleting through base pointer. Prevents memory leaks.
  • Q: Can we instantiate an abstract class?
    A: No.
  • Q: What is the diamond problem?
    A: Multiple inheritance issue solved with virtual inheritance.
  • Q: Can constructors be virtual?
    A: No. vtable is set up after constructor runs.
  • Q: What is a pure virtual function?
    A: virtual void f() = 0; – makes class abstract.
  • Q: What is vtable and vptr?
    A: vtable = array of function pointers; vptr = pointer to vtable (per object).
  • Q: What is the size of an empty class?
    A: 1 byte (to ensure unique addresses).
  • Q: Explain method chaining.
    A: Returning *this to allow cascaded calls: obj.setA().setB().show();
