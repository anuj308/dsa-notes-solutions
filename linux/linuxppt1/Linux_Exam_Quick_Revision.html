Linux System Administration

Exam Quick Revision & Practical Command Guide

CSE 493 · Units I–VI

Prepared from the course syllabus, Linux presentations, practical questions, shell notes, networking/storage examples, and revision files in linuxppt1.

How to use tonight: Read the command tables once, practise the 15 Unit I–II scenarios, then revise the bold “must remember” points. Never run destructive storage commands on a real machine without confirming the device.

Linux commands may vary slightly between RHEL versions. Use man command and command --help when in doubt.

1. Exam strategy and command pattern

Scenario → command → verify. For almost every practical, first inspect the current state, make one change, then verify with a read-only command. Use sudo only when required.
NeedUseful commands
Current location and filespwd, ls -la, cd /path
Helpman cmd, cmd --help, info cmd, apropos keyword
Verify identitywhoami, id, hostname
Read safelycat, less, head, tail
Find and filterfind, grep, grep -E, pipes |

2. Unit I — command line, files, help, users

Navigation and file operations

cd /etc
ls -lah

cp source.txt backup/
mv old.txt new.txt
rm -i file.txt       # ask before deleting

Finding files and shell expansion

find /etc -type f -name '*.conf' 2>/dev/null
find . -type f -iname '*report*'
ls data*.txt
ls report?.txt
# redirection
printf 'pwd\nls\nid\n' > linux_commands.txt
printf 'date\nwhoami\n' >> linux_commands.txt
cat linux_commands.txt

Text and documentation

less file.txt
head -n 10 file.txt
tail -f /var/log/messages
man chmod                 # search inside man: /pattern; quit: q
man -k password           # keyword search (same idea as apropos)
apropos permissions
info coreutils 'ls'

Users and groups

sudo groupadd developers
sudo useradd -m developer1
sudo useradd -m developer2
sudo usermod -aG developers developer1
sudo usermod -aG developers developer2
sudo passwd developer1
id developer1
groups developer1
getent group developers
sudo userdel -r developer1   # only when deletion is intended
Remember: usermod -aG means append supplementary groups. Without -a, existing supplementary groups can be replaced.

4. Unit III — networking, archives, packages, filesystems

Network inspection and nmcli

Archives, packages, links

tar -czf backup.tar.gz directory/
tar -tzf backup.tar.gz
tar -xzf backup.tar.gz
scp file user@host:/tmp/
rsync -av directory/ user@host:/backup/
sudo dnf search keyword

Mounting filesystems

lsblk
sudo fdisk -l
sudo blkid
sudo mkdir -p /data
sudo mkfs.xfs /dev/sdb1       # destroys data on that partition
sudo mount /dev/sdb1 /data
df -hT
findmnt /data
sudo umount /data
# persistent mount: use UUID from blkid in /etc/fstab
UUID=XXXX  /data  xfs  defaults  0 0
sudo mount -a
Safety: Confirm the device with lsblk before fdisk, mkfs, mount, umount, or mkswap. A wrong device can erase data.

5. Unit IV — Bash, loops, regex, scheduling, performance, ACL

Bash script template

#!/bin/bash
read -p 'Marks: ' marks
if [ "$marks" -ge 40 ]; then
  echo 'PASS'
else
  echo 'FAIL'
fi
# save as check.sh, then:
chmod +x check.sh
./check.sh

Loops and conditions

for n in 1 2 3; do echo "$n"; done
for f in *.txt; do echo "$f"; done
n=1
while [ "$n" -le 5 ]; do echo "$n"; n=$((n+1)); done
if [ -f file.txt ]; then echo exists; fi
[ "$a" -gt "$b" ] && echo greater

Regular expressions and grep

grep '^ERROR' app.log       # beginning of line
grep 'failed$' app.log      # end of line
grep -E 'error|failed' app.log
grep -E '^[0-9]{5}$' file.txt
grep -i 'warning' log.txt
grep -v '^#' config.txt       # exclude comments
RegexMeaning
^, $start, end of line
.any one character
[abc], [0-9]one character from a set/range
*, +, ?zero-or-more, one-or-more, optional (extended regex)
{n}, {n,m}exact/ranged repetition with grep -E

Scheduling and ACL

at now + 5 minutes
# type commands, then Ctrl+D
atq
at -c JOB_ID
atrm JOB_ID
crontab -e
# minute hour day month weekday command
setfacl -m u:alice:rw file

6. Unit V — SELinux, partitions, swap, LVM, Stratis/VDO

SELinux quick checks

getenforce
sestatus
sudo setenforce 0       # temporary permissive; use only when instructed
ls -Z
sudo restorecon -Rv /var/www/html
getsebool -a
sudo ausearch -m AVC -ts recent

Partitions, swap, and LVM concepts

lsblk
sudo fdisk /dev/sdb
sudo mkfs.xfs /dev/sdb1
sudo mkswap /dev/sdb2
sudo swapon /dev/sdb2
swapon --show
sudo swapoff /dev/sdb2
# LVM conceptual workflow:
sudo pvcreate /dev/sdb1
sudo vgcreate vgdata /dev/sdb1
sudo lvcreate -n lvdata -L 2G vgdata
sudo mkfs.xfs /dev/vgdata/lvdata
sudo mount /dev/vgdata/lvdata /data
sudo lvextend -r -L +1G /dev/vgdata/lvdata
Persistent configuration: use UUIDs in /etc/fstab; test with mount -a. For swap, the fstab entry uses none swap defaults 0 0.

8. Fifteen practical scenarios — model answers

  1. pwd; cd /etc; ls -l; cd /var/log; cd ~
  2. find /etc -type f -name '*.conf' 2>/dev/null
  3. mkdir -p ~/LinuxAssessment/{commands,reports,backup}; touch ~/LinuxAssessment/commands/cmd{1,2,3}.txt; find ~/LinuxAssessment -print
  4. touch data{1,2,3}.txt report{1,2}.txt; printf '%s\n' data*.txt; printf '%s\n' report*.txt
  5. printf 'pwd\nls\nid\n' > linux_commands.txt; cat linux_commands.txt; printf 'date\nwhoami\n' >> linux_commands.txt
  6. man chmod; search inside with /OPTIONS; installed keyword search with apropos keyword or man -k keyword.
  7. sudo groupadd developers; sudo useradd -m developer1; sudo useradd -m developer2; sudo usermod -aG developers developer1 developer2; getent group developers
  8. sudo useradd -m labuser; sudo passwd labuser; id labuser; getent passwd labuser
  9. touch project.txt; chmod 640 project.txt; stat -c '%A %a %n' project.txt
  10. mkdir shared_lab; chmod 750 shared_lab; stat -c '%A %a %n' shared_lab
  11. Run sleep 300; press Ctrl+Z; run bg; jobs; fg.
  12. ps -u "$USER"; kill PID; ps -p PID
  13. systemctl status sshd; sudo systemctl enable sshd; systemctl is-enabled sshd
  14. ssh "$USER"@localhost; whoami; hostname; pwd; exit
  15. journalctl -n 50; journalctl -u sshd; journalctl -u sshd -r; journalctl -p warning -b

9. Last-minute checklist

  • Can you explain the permission digits 640 and 750?
  • Can you distinguish find from grep?
  • Can you use systemctl to inspect, start, stop, enable, and verify a service?
  • Can you inspect a network using nmcli, ip, and ping?
  • Can you create a filesystem, mount it, and make it persistent using UUID/fstab?
  • Can you explain SELinux enforcing/permissive and read an AVC denial?
  • Can you write an if script and a for/while loop?
  • Can you schedule one deferred job with at and recurring jobs with cron?
  • For every command, can you state how you will verify the result?
