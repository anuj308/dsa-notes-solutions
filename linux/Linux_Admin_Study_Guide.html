📘 Unit I — Accessing the Command Line & Managing Files

1. What is Linux?

Linux is a free, open-source operating system created by Linus Torvalds in 1991. It is used in servers, supercomputers, phones (Android), cloud computing, and IoT devices.

Why learn Linux? It powers most of the internet's servers, is in high demand for IT jobs, and is the foundation of cloud computing.

2. Linux Architecture

Think of Linux as layers:

LayerWhat It Does
HardwarePhysical parts (CPU, RAM, disk)
KernelThe core — manages hardware, memory, processes. Talks to hardware.
ShellThe command interpreter. You type commands here. Example: Bash
ApplicationsPrograms you use (text editors, browsers, etc.)

3. Accessing the Command Line

The command line is a text interface where you type instructions to the computer.

  • Physical Console — Directly connected keyboard + monitor
  • Virtual Consoles — Switch between them with Ctrl+Alt+F1 to Ctrl+Alt+F6
  • SSH (Remote) — Connect over network: ssh username@hostname
# Login to a remote system
ssh student@192.168.1.10

# Logout
exit

4. Shell Basics

Every command has three parts: Command + Options + Arguments

ls -l /home
↑ command    ↑ option    ↑ argument

Shell Prompt:

  • Regular user: [user@host ~]$
  • Root (admin): [root@host ~]#
# whoami — shows current user
whoami

# Multiple commands on one line (separated by ;)
whoami ; hostname ; pwd

5. Linux File System Hierarchy

Linux has a tree-like directory structure starting from / (root):

Absolute path starts from / (e.g., /home/user/file.txt). Relative path starts from your current location (e.g., ../Documents/report.txt).

12. Users and Groups

Linux uses user accounts for security. Every account has:

  • UID (User ID) — unique number for each user
  • GID (Group ID) — the user's primary group number
  • Home Directory — personal folder (e.g., /home/student)
  • Login Shell — which shell to use (usually /bin/bash)
# Create users

passwd sales_emp1              # Set password

groupadd sales                 # Create sales group

grep sales_emp1 /etc/passwd     # Full account info

usermod -aG support sales_emp1   # Add to supplementary group

userdel -r emp1                # Delete user and home dir

# Groups

groups user1                   # Show all groups for user1

📗 Unit II — Permissions, Processes, Services, SSH, Logs

1. File Permissions

Every file/directory has 3 types of permissions for 3 classes of users:

PermissionFor FilesFor Directories
r (read)View file contentsList directory contents
w (write)Modify file contentsCreate/delete files inside
x (execute)Run as a programEnter (cd into) the directory

Permissions are shown with ls -l:

-rwxr-xr-- 1 owner group 4096 Jan 1 10:00 file.txt
↑ type  ↑ owner( rwx)  ↑ group( r-x)  ↑ others( r--)
# Symbolic method
chmod u+x file.txt      # Add execute for owner
chmod g-w file.txt      # Remove write for group
chmod o=r file.txt       # Set others to read-only
chmod a+r file.txt       # Add read for everyone

# Numeric (octal) method
# r=4, w=2, x=1
chmod 755 file.txt       # rwxr-xr-x
chmod 644 file.txt       # rw-r--r--
chmod 700 dir/          # rwx------ (only owner)

# Change ownership
chown user1 file.txt      # Change owner
chown user1:group1 file.txt # Change owner and group
chown -R user1:group1 dir/ # Recursive change

2. Special Permissions

PermissionWhat It DoesSymbolNumber
SetUIDRuns with owner's permissionsu+s4
SetGIDRuns with group's permissions / Files inherit groupg+s2
Sticky BitOnly file owner can delete their fileso+t1
chmod u+s /usr/bin/passwd   # SetUID — lets normal users change passwords
chmod g+s project/           # SetGID — new files inherit group
chmod o+t /tmp/              # Sticky bit — only owner can delete
chmod 4755 file               # Numeric: 4=SetUID

3. Processes

A process is a running program. Each process gets a unique PID (Process ID).

Process States:

StateMeaning
RRunning or Ready to run
SSleeping (waiting for event)
TStopped (suspended)
ZZombie (terminated but parent hasn't read exit status)
# View processes
ps aux                 # Show all processes
ps -ef                 # Show all with PPID
top                   # Real-time monitoring (press q to quit)
ps aux | grep process_name # Find specific process

# Kill processes
kill PID              # Send TERM signal (graceful)
kill -9 PID           # Send KILL signal (force)
killall process_name   # Kill all by name
pkill process_name     # Kill by pattern

# Job control
sleep 100            # Start foreground job
Ctrl+Z               # Suspend it
bg                   # Send to background
jobs                 # List background jobs
fg %1               # Bring job 1 to foreground
command &           # Run command in background directly

4. Services and Daemons

A daemon is a background service that runs without user interaction. systemd manages all services.

# Check service status
systemctl status sshd         # Check if SSH is running

# Start/Stop/Restart services
systemctl start sshd          # Start the service
systemctl stop sshd           # Stop the service
systemctl restart sshd         # Restart (stop + start)
systemctl reload sshd         # Reload config without stopping

# Enable/Disable at boot
systemctl enable sshd          # Auto-start at boot
systemctl disable sshd         # Don't start at boot
systemctl is-enabled sshd      # Check if enabled

# List all services
systemctl list-unit-files --type=service

5. SSH (Secure Shell)

SSH lets you securely connect to remote systems over the network. Everything is encrypted.

# Connect to remote system
ssh student@192.168.1.10     # Uses password

# Key-based authentication (no password needed!)
ssh-keygen -t rsa             # Generate key pair
ssh-copy-id student@192.168.1.10 # Copy public key to server
ssh student@192.168.1.10        # Now connects without password

# Copy files
scp file.txt student@remote:/tmp/ # Copy file to remote
scp student@remote:/var/log/secure . # Copy from remote to local
SSH key-based authentication is more secure than passwords and is a common exam topic!

6. Logs and Troubleshooting

Linux stores logs to help you troubleshoot problems. journald (systemd journal) is the modern logging system.

journalctl -u sshd          # Logs for SSH service
journalctl -f               # Follow logs in real-time
journalctl -p err           # Show errors only
journalctl --since "1 hour ago" # Logs from last hour

# Preserve logs to a file
journalctl > /tmp/system_report.txt

# Log files
cat /var/log/secure          # Login/auth logs
cat /var/log/messages        # General system logs

5. Hard Links vs Soft Links

Hard Link

  • Points to the same inode (data) as the original
  • Changes to one affect the other
  • If original is deleted, hard link still works
  • Cannot cross filesystems
  • Command: ln file1 file2

Soft (Symbolic) Link

  • Points to the path/name of the original
  • Has its own inode number
  • If original is deleted, link breaks
  • Can cross filesystems
  • Command: ln -s file1 file2

📕 Unit IV — Bash Scripting, Scheduling, Performance, ACLs

1. Bash Scripting Basics

A shell script is a text file containing a series of commands. Create with vim, make executable with chmod +x, and run with ./script.sh.

#!/bin/bash
# This is a comment
echo "Hello, $USER!"
echo "Today is $(date)"
echo "Your home is $HOME"

# Variables
NAME="Linux"
echo "Welcome to $NAME"

# Positional parameters
echo "Script name: $0"
echo "First argument: $1"
echo "Second argument: $2"

# Run: ./script.sh arg1 arg2

2. Conditional Statements (if/else)

#!/bin/bash
FILE="/etc/passwd"

if [ -f "$FILE" ]; then
    echo "$FILE exists"
elif [ -d "$FILE" ]; then
    echo "$FILE is a directory"
else
    echo "$FILE does not exist"
fi

# Common test conditions:
# -f file exists -d directory exists
# -e exists -r readable
# -w writable -x executable
# -z string is empty -n string not empty
# = equal != not equal

3. Loops

#!/bin/bash

# For loop
for i in 1 2 3 4 5; do
    echo "Number: $i"
done

# Loop through files
for file in *.txt; do
    echo "Processing $file"
done

# C-style for loop
for ((i=1; i<=5; i++)); do
    echo "Count: $i"
done

ACLs give you finer control over permissions beyond the basic owner/group/other model.

📓 Unit V — SELinux, Storage, LVM

1. SELinux (Security-Enhanced Linux)

SELinux is an extra security layer that controls what processes can do. It labels files and processes.

ModeWhat Happens
EnforcingBlocks unauthorized access (default, recommended)
PermissiveLogs violations but doesn't block (good for testing)
DisabledSELinux is off (not recommended)
# Check SELinux status
getenforce                # Shows Enforcing/Permissive/Disabled
sestatus                  # Detailed status

# Change mode (temporary — resets on reboot)
setenforce 0             # Set to Permissive
setenforce 1             # Set to Enforcing

# Change mode permanently — edit /etc/selinux/config
# SELINUX=enforcing

# File contexts (labels)
ls -Z file.txt            # View file context
restorecon -v file.txt     # Restore default context
semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
restorecon -Rv /web        # Apply new context

# Booleans
getsebool -a | grep httpd  # List relevant booleans
setsebool -P httpd_can_network_connect on # Allow httpd network

2. LVM (Logical Volume Management)

LVM lets you create flexible storage. You can resize volumes without reformatting.

LVM Layers: Physical Volumes → Volume Groups → Logical Volumes

# Step 1: Create Physical Volume
pvcreate /dev/sdb          # Initialize disk as PV
pvs                       # List physical volumes

# Step 2: Create Volume Group
vgcreate my_vg /dev/sdb     # Create VG from PV
vgs                       # List volume groups

# Step 3: Create Logical Volume
lvcreate -L 5G -n my_lv my_vg # Create 5GB logical volume
lvs                       # List logical volumes

# Step 4: Format and mount
mkfs.xfs /dev/my_vg/my_lv
mkdir /data
mount /dev/my_vg/my_lv /data

# Extend logical volume
lvextend -L +2G /dev/my_vg/my_lv
xfs_growfs /data          # Grow XFS filesystem
resize2fs /dev/my_vg/my_lv # Grow ext4 filesystem

3. Swap Space

Swap is "virtual RAM" on disk — used when physical RAM is full.

# Check swap
free -h
swapon --show

# Create swap file
dd if=/dev/zero of=/swapfile bs=1M count=1024
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
# Add to /etc/fstab for persistence:
# /swapfile swap swap defaults 0 0

📝 Sample Assignment (CA-1) — All 10 Questions with Detailed Answers

Scenario: An e-commerce company uses a Linux server for order processing. You must create user access, secure files, and troubleshoot processes.

Q1. Create sales and support groups and create appropriate employee accounts.

Answer:

Step 1: Create the groups
sudo groupadd sales
sudo groupadd support
Step 2: Create employee accounts with primary group set
# Create sales employees
sudo useradd -m -g sales sales_emp1
sudo useradd -m -g sales sales_emp2

# Create support employees
sudo useradd -m -g support support_emp1
sudo useradd -m -g support support_emp2
Step 3: Verify
getent group sales
getent group support
# Expected output shows members listed after the group

Q2. Configure passwords and verify UID, GID, primary group, supplementary groups, and login shell.

Answer:

Step 1: Set passwords for each employee
sudo passwd sales_emp1
# Enter new password when prompted
Step 2: Verify all account details using id command
id sales_emp1
# Output example: uid=1001(sales_emp1) gid=1001(sales) groups=1001(sales)

# More detailed info from /etc/passwd
grep sales_emp1 /etc/passwd
# Output: sales_emp1:x:1001:1001::/home/sales_emp1:/bin/bash
# Fields: username:password:UID:GID:comment:home:shell

# Check supplementary groups
groups sales_emp1
Step 3: Add supplementary group (make sales person also in support)
sudo usermod -aG support sales_emp1
groups sales_emp1
# Output: sales_emp1 : sales support

Q3. Create /orders with pending, completed, and backup directories.

Answer:

# Create the directory structure
sudo mkdir -p /orders/pending
sudo mkdir -p /orders/completed
sudo mkdir -p /orders/backup

# Verify the structure
ls -ld /orders/*
# Or use tree if available:
tree /orders
The -p flag in mkdir creates parent directories as needed. If /orders doesn't exist, it creates it too.

Q4. Create sample order files and use shell expansion to copy multiple order files to the backup directory.

Answer:

Step 1: Create sample order files
# Create order files in pending directory
touch /orders/pending/order001.txt
touch /orders/pending/order002.txt
touch /orders/pending/order003.txt
touch /orders/pending/order004.txt
touch /orders/pending/order005.txt

# Verify
ls /orders/pending/
Step 2: Use shell expansion (wildcards) to copy multiple files
# Copy ALL order files using * wildcard
cp /orders/pending/order*.txt /orders/backup/

# Or copy only specific ones using []
cp /orders/pending/order00[1-3].txt /orders/backup/

# Verify the copy
ls -la /orders/backup/
Shell expansion happens BEFORE the command runs. The shell replaces order*.txt with the actual list of matching filenames.

Q5. Locate a particular order file by name using an appropriate file-search command.

Answer:

# Method 1: Using find (searches from a starting point)
find /orders -name "order003.txt"

# Search by pattern
find /orders -name "order*.txt"

# Suppress permission-denied errors
find /orders -name "order*.txt" 2>/dev/null

# Method 2: Using locate (faster, uses database)
updatedb                 # Update database first
locate order003.txt

# Method 3: Using grep to search file contents
grep -r "order003" /orders/
find is best for exact searches. locate is faster for quick lookups but needs updatedb to be current.

Q6. Configure ownership and permissions so that only authorized employees can modify order files.

Answer:

# Step 1: Set ownership — sales group owns /orders
sudo chown -R root:sales /orders

# Step 2: Set directory permissions
# Owner(root) and group(sales) can read/write/execute
# Others have no access
sudo chmod -R 770 /orders

# Step 3: Set the setgid bit on /orders
# New files automatically inherit the sales group
sudo chmod g+s /orders

# Step 4: Set default permissions for new files
# Only owner and group can modify, others read-only
sudo setfacl -d -m g:sales:rwx /orders

# Verify permissions
ls -la /orders/
getfacl /orders

Q7. Redirect the output of a suitable system command into /orders/system_report.txt.

Answer:

# Redirect system information to a report file
# Using > creates/overwrites the file

echo "=== System Report ===" > /orders/system_report.txt
echo "Date: $(date)" >> /orders/system_report.txt
echo "Hostname: $(hostname)" >> /orders/system_report.txt
echo "Uptime:" >> /orders/system_report.txt
uptime >> /orders/system_report.txt
echo "" >> /orders/system_report.txt
echo "=== Disk Usage ===" >> /orders/system_report.txt
df -h >> /orders/system_report.txt
echo "" >> /orders/system_report.txt
echo "=== Memory Usage ===" >> /orders/system_report.txt
free -h >> /orders/system_report.txt

# Verify
cat /orders/system_report.txt
Use > for the first line (creates/overwrites), then >> for all subsequent lines (appends without deleting).

Q8. Identify a resource-consuming process and terminate it safely after verifying its PID.

# Press 'P' to sort by CPU, 'M' to sort by memory
# Press 'q' to quit top

ps aux --sort=-%cpu | head -5
# This shows top 5 CPU consumers

# Step 3: Note the PID of the dd process

# Output example: 12345 dd

# Step 4: Kill it gracefully first (SIGTERM = signal 15)

# Step 5: If it doesn't stop, force kill (SIGKILL = signal 9)

Always try kill PID (SIGTERM) first. Only use kill -9 PID (SIGKILL) if the process doesn't respond. SIGTERM gives the process a chance to clean up.

P11. What is the difference between > and >> in Linux redirection? Give an example of each.

Answer:

# > OVERWRITES the file (deletes old content)
echo "First line" > myfile.txt
echo "Second line" > myfile.txt
# myfile.txt now contains ONLY "Second line"

# >> APPENDS to the file (keeps old content)
echo "First line" > myfile.txt
echo "Second line" >> myfile.txt
# myfile.txt contains both lines
Think: > = "replace" and >> = "add to end".

P15. Explain what happens when you type "ls -la" at the command prompt. Describe the layers involved.

Answer:

1. You type ls -la and press Enter at the shell prompt.
2. The shell (Bash) reads your input.
3. The shell parses it: command = ls, options = -la.
4. The shell searches $PATH to find the ls binary (usually /usr/bin/ls).
5. The shell creates a new process (via fork() + exec()).
6. The ls program runs with -l (long format) and -a (show hidden files) options.
7. The kernel reads the directory data from disk and passes it to the ls process.
8. ls formats the output and sends it to stdout (standard output = your screen).
9. The shell displays the output and gives you a new prompt.

🎯 Exam Tips for CA-1
  1. Always verify your work. After creating users, run id username. After setting permissions, run ls -l.
  2. Use the right tool. find for searching files, grep for searching inside files.
  3. Remember shell expansion. Wildcards (*, ?, []) expand BEFORE the command runs.
  4. Redirect carefully. > overwrites, >> appends. Don't accidentally overwrite important files!
  5. Process killing: Always try kill PID (graceful) before kill -9 PID (force).
  6. Time management: This is a practical exam. Don't spend too long on one question. Move on and come back.
  7. Check service status AND enable it. systemctl status checks if running, systemctl enable makes it start at boot.
  8. For journalctl: Use -u for service, -n for number of lines, -f to follow, -r for reverse, -p for priority.
