📖 Unit I — Command Line & File Management

🔹 Accessing the Command Line

  • Bash Shell is the default shell (/bin/bash).
  • Prompt: $ for normal user, # for root.
  • Access via local console (Ctrl+Alt+F1–F6), desktop (GNOME Terminal), or SSH (remote).
  • Command syntax: command [options] [arguments]

🔹 Linux File System Hierarchy (FHS)

DirectoryPurpose
/Root — top of the tree
/bootKernel, initramfs, GRUB2
/etcSystem configuration files
/homeUser home directories
/rootHome directory for root user
/varVariable data — logs, spool, cache
/tmpTemporary files (cleared after 10 days)
/usrUser system resources — binaries, libraries
/devDevice files (block & character)
/procVirtual — kernel and process info
/sysVirtual — device and driver info

🔹 Getting Help

  • man command — Manual pages (Section 1 = user commands, Section 5 = file formats)
  • man -k keyword or apropos keyword — Search manuals
  • whatis command — One-line description
  • /usr/share/doc/ — Package documentation

📖 Unit II — Permissions, Processes, Logs & SSH

🔹 File Permissions (ugo/rwx)

PermissionEffect on FileEffect on Directory
r (read)Can read file contentsCan list contents (ls)
w (write)Can modify fileCan create/delete files (needs x as well)
x (execute)Can run as programCan cd into directory

Octal permissions:

OctalSymbolicMeaning
7rwxRead + Write + Execute
6rw-Read + Write
5r-xRead + Execute
4r--Read only
0---No permissions

🔹 Special Permissions

SETUID (4xxx)

chmod u+s file — Run file with owner's permissions.
Example: /usr/bin/passwd runs as root.

SETGID (2xxx)

chmod g+s dir — New files inherit group of parent directory.
Use: Shared team folders.

Sticky Bit (1xxx)

chmod o+t dir — Only file owners can delete files in shared directories.
Example: /tmp.

🔹 Processes

  • Process = Running instance of a program. Each has a PID (Process ID) and PPID (Parent PID).
  • States: R (running), S (sleeping), D (uninterruptible), T (stopped), Z (zombie).
  • ps aux — Snapshot of all processes.
  • top — Real-time process monitor.
  • kill -9 PID — Force kill (SIGKILL).
  • kill -15 PID — Graceful terminate (SIGTERM, default).
  • pkill process_name — Kill by name.
  • Nice values: -20 (highest priority) to +19 (lowest). Default = 0.

🔹 Job Scheduling

  • at — One-time job: at 2:30pm then type commands, Ctrl+D to finish.
  • cron — Recurring jobs: crontab -e to edit.

Crontab syntax: min hour day month weekday command

* * * * * /usr/bin/echo "Hello" >> /tmp/hello.txt

Explanation: Every minute, every hour, every day, every month, every weekday.

🔹 SSH (Secure Shell)

  • Default port: 22
  • Key-based authentication is more secure than passwords.
  • ssh-keygen — Generate key pair (~/.ssh/id_rsa private, id_rsa.pub public).
  • ssh-copy-id user@host — Copy public key to remote server.
  • sftp user@host — Secure file transfer.

🔹 System Logs

  • /var/log/messages — General system logs.
  • /var/log/secure — Authentication logs (SSH, sudo).
  • /var/log/boot.log — Boot process logs.
  • journalctl — View systemd journal logs.
  • journalctl -u sshd — Logs for sshd service.
  • Persistent journal: Create /var/log/journal directory.
📝 Exam Tip: Practice chmod with both symbolic (u+x) and octal (755) methods.
Know how to add users to groups, lock/unlock users with passwd -l / usermod -L, and set password aging with chage.

📝 BYOD Practical — Order Processing System

Question: E-commerce company uses Linux server. Perform these tasks:

Task 1-2: Users & Groups

  • Create sales and support groups.
  • Create employee accounts.
  • Verify UID, GID, primary/supplementary groups, login shell.
sudo groupadd sales
sudo useradd -G sales -s /bin/bash emp1
sudo id emp1

Task 3-5: Directory & Files

  • Create /orders with pending/, completed/, backup/.
  • Create sample order files.
  • Use shell expansion to copy to backup.
  • Locate file by name with find.
sudo mkdir -p /orders/{pending,completed,backup}
sudo touch /orders/pending/order{1..5}.txt
sudo cp /orders/pending/*.txt /orders/backup/
sudo find /orders -name "order3.txt"

Task 6-8: Permissions & Processes

  • Configure ownership/permissions so only authorized employees can modify.
  • Redirect output to /orders/system_report.txt.
  • Find resource-consuming process and terminate safely.
sudo chown -R :sales /orders
sudo chmod -R 770 /orders
ps aux --sort=-%cpu | head
sudo kill -15 PID

Task 9-10: Services & Time

  • Check service and inspect journal entries.
  • Verify system time and preserve diagnostic info.
sudo systemctl status sshd
sudo journalctl -u sshd
timedatectl
date > /orders/time_info.txt
💡 Key commands for this practical: groupadd, useradd, id, groups, mkdir -p, touch, cp, find, chown, chmod, ps, kill, systemctl, journalctl, timedatectl, date, redirection (>).

🧪 Practice Scenarios

Scenario 1: User Management

Create group developers (GID 5000).
Create users dev1 and dev2 with home directories and bash shell.
Add both to developers as supplementary members.
Set password dev123 for both.

sudo groupadd -g 5000 developers
sudo useradd -m -s /bin/bash dev1
sudo usermod -aG developers dev1
echo "dev1:dev123" | sudo chpasswd

Scenario 2: File Permissions

Create /project directory.
Set ownership: group = developers.
Permissions: owner full (rwx), group read+execute (rx), others no access.
Enable SETGID so new files inherit group.

sudo mkdir /project
sudo chown :developers /project
sudo chmod 750 /project
sudo chmod g+s /project

Scenario 3: Cron Job

Schedule a job to run every day at 2:30 AM.
Command: /usr/bin/backup.sh
Redirect output to /var/log/backup.log.

crontab -e
30 2 * * * /usr/bin/backup.sh >> /var/log/backup.log 2>&1

Scenario 4: NFS & AutoFS

On server: share /exports/data with rw to client.
On client: configure AutoFS to mount /exports/data on /mnt/data when accessed.

# On NFS server
echo "/exports/data *(rw)" >> /etc/exports
exportfs -av
# On client
echo "/mnt /etc/auto.misc" >> /etc/auto.master
echo "data -rw server:/exports/data" > /etc/auto.misc
systemctl restart autofs
