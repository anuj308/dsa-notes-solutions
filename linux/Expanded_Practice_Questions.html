Q4. Explain the difference between > and >> with examples. What happens if you accidentally use > when you meant >>?

Answer:

# > OVERWRITES — creates new file or REPLACES contents echo "Line 1" > file.txt echo "Line 2" > file.txt cat file.txt # Output: Line 2 (Line 1 is GONE!) # >> APPENDS — adds to end, keeps existing content echo "Line 1" > file.txt echo "Line 2" >> file.txt cat file.txt # Output: # Line 1 # Line 2
If you accidentally use > instead of >>, you will LOSE all previous content in that file. There is no undo! Always double-check before pressing Enter.
Real-world scenario: You're building a system report throughout the day. Use > for the header once, then >> for every additional section.
date > /tmp/report.txt # Create file with date hostname >> /tmp/report.txt # Append hostname df -h >> /tmp/report.txt # Append disk info free -h >> /tmp/report.txt # Append memory info

Q5. What does 2> do? What does 2>&1 mean? Create a command that saves both output and errors to one file.

Answer:

# In Linux, there are 3 streams: # 0 = stdin (input) # 1 = stdout (normal output) — default # 2 = stderr (error messages) # 2> redirects ERRORS to a file find /etc -name "*.conf" 2> /tmp/errors.txt # Normal results go to screen, errors go to errors.txt # 2>&1 means "redirect stderr to wherever stdout is going" # This combines BOTH output and errors into one file: find /etc -name "*.conf" > /tmp/all_output.txt 2>&1 # Now both results AND errors are in all_output.txt # Short version (bash shortcut): find /etc -name "*.conf" &> /tmp/all_output.txt
Think of it this way: 2>&1 = "make error (2) go to the same place as normal output (1)".

Q7. Create groups "managers" and "developers". Create users bob (in managers), carol and dave (in developers). Make bob also a member of developers. Verify all memberships.

Answer:

# Step 1: Create groups sudo groupadd managers sudo groupadd developers # Step 2: Create users with primary groups sudo useradd -m -g managers bob sudo useradd -m -g developers carol sudo useradd -m -g developers dave # Step 3: Add bob to developers as supplementary group # -a means APPEND (don't remove existing groups!) sudo usermod -aG developers bob # Step 4: Verify all memberships echo "=== Bob ===" id bob # uid=1001(bob) gid=1001(managers) groups=1001(managers),1002(developers) echo "=== Carol ===" id carol # uid=1002(carol) gid=1002(developers) groups=1002(developers) echo "=== Dave ===" id dave # uid=1003(dave) gid=1002(developers) groups=1002(developers) # Alternative: check group membership groups bob # Output: bob : managers developers

Q8. A file has permissions -rwxr-x---. Explain what each part means in plain English. Then write the chmod command to change it to rw-rw-r-- using numeric notation.

Answer — Reading the permission string:

# -rwxr-x--- # | | | # | | └── Others (---) = no read, no write, no execute # | └─────── Group (r-x) = read, no write, execute # └─────────── Owner (rwx) = read, write, execute # Plain English: # - The owner can read, write, and run this file # - Members of the group can read and run it, but cannot modify it # - Everyone else has NO access at all
Now change to rw-rw-r--:
# Numeric calculation: # rw- = 4+2+0 = 6 # rw- = 4+2+0 = 6 # r-- = 4+0+0 = 4 # Result: 664 chmod 664 filename.txt # Verify: ls -l filename.txt # Output: -rw-rw-r-- 1 user group ... filename.txt

Q9. What is the SetGID bit? Why would you use it on a shared directory? Create a shared project directory, enable SetGID, create a file inside it, and verify the group inheritance.

Answer:

What is SetGID? When SetGID is set on a directory, any new files created inside it automatically inherit the directory's group (instead of the creator's primary group). This is essential for team collaboration.
# Step 1: Create a shared directory owned by the developers group sudo mkdir /project sudo chown root:developers /project # Step 2: Set permissions (775) and enable SetGID sudo chmod 2775 /project # The "2" sets the SetGID bit # 7=rwx for owner, 7=rwx for group, 5=r-x for others # Alternative using symbolic: sudo chmod g+s /project # Step 3: Verify SetGID is set (notice the 's' in group position) ls -ld /project # Output: drwxrwsr-x 2 root developers 4096 ... /project # ↑ 's' means SetGID # Step 4: Create a file as a user in the developers group su - carol touch /project/carol_report.txt ls -l /project/carol_report.txt # Output: -rw-rw-r-- 1 carol developers ... carol_report.txt # ↑ ↑ # owner group = developers (inherited!) # Without SetGID, group would be "carol" instead

⚙️ Section 3 — Process Control (Jobs, bg/fg, Signals)

Q11. You start a command that takes too long. Describe the exact steps to: suspend it, move to background, list all jobs, bring job #1 to foreground, and then kill it from the foreground.

Answer — Complete workflow:

# 1. Start a long-running process dd if=/dev/zero of=/tmp/bigfile bs=1M count=1000 # Terminal is now blocked — you can't type anything # 2. SUSPEND it with Ctrl+Z ^Z # Output: [1]+ Stopped dd if=/dev/zero... # You now have your terminal back! # 3. Move to BACKGROUND bg %1 # Output: [1]+ dd if=/dev/zero ... & # The process continues running in background # 4. List all active jobs jobs # Output: [1]+ Running dd if=/dev/zero ... & # 5. Bring to foreground fg %1 # You're back in the dd process — terminal is blocked again # 6. Kill it (Ctrl+C sends SIGINT = graceful stop) ^C # Process terminated
Key shortcuts:
# Ctrl+Z → Suspend current process # bg %N → Resume job N in background # fg %N → Bring job N to foreground # jobs → List all background/suspended jobs # Ctrl+C → Kill foreground process (SIGINT) # Ctrl+D → End-of-file / logout

Q25. Explain what happens when you type "cat /etc/passwd | grep alice | wc -l" at the command line. Describe piping, each command's role, and how data flows.

Answer:

# The command: cat /etc/passwd | grep alice | wc -l # Data flow (left to right): # ┌─────────────┐ ┌──────────────┐ ┌──────────────┐ # │ cat /etc/ │ ──→ │ grep alice │ ──→ │ wc -l │ # │ passwd │ │ │ │ │ # │ │ │ Filters only │ │ Counts lines │ # │ Outputs all │ │ lines with │ │ and prints │ # │ lines in │ │ "alice" │ │ the number │ # │ passwd file │ │ │ │ │ # └─────────────┘ └──────────────┘ └──────────────┘ # Step 1: cat /etc/passwd # Reads the entire /etc/passwd file # Output: all user account lines (maybe 30+ lines) # Step 2: | (pipe) sends cat's output as input to grep # Step 3: grep alice # Scans each line and keeps only lines containing "alice" # Output: maybe 2-3 lines (alice:x:1001:1001:...) # Step 4: | (pipe) sends grep's output as input to wc # Step 5: wc -l # Counts the lines it received # Output: 3 (meaning 3 lines matched)
The pipe | is like a conveyor belt. Each command's output becomes the next command's input. Data flows left → right.

Q29. A user reports they can't write to a directory even though they own files inside it. List 5 possible causes and how to diagnose each.

Answer — 5 possible causes:

# CAUSE 1: The DIRECTORY doesn't have write permission ls -ld /path/to/directory/ # If there's no 'w' for user/group → chmod to fix chmod u+w /path/to/directory/ # CAUSE 2: The filesystem is mounted read-only mount | grep /path # If shows "ro" → remount as read-write sudo mount -o remount,rw /path # CAUSE 3: Disk is full df -h /path/to/directory/ # If Use% = 100% → free up space sudo du -sh /path/* | sort -rh | head -10 # find large files # CAUSE 4: SELinux is blocking access ls -Z /path/to/directory/ # If context is wrong → restore correct context sudo restorecon -Rv /path/to/directory/ # Or check audit log: sudo ausearch -m avc --raw | grep denied # CAUSE 5: ACL is denying access getfacl /path/to/directory/ # If ACL shows deny entry → fix with setfacl sudo setfacl -m u:username:rwx /path/to/directory/

Q30. Create a complete scenario: You're setting up a Linux server for a small company. Write a shell script that automates: creating 3 departments (HR, IT, Sales), creating users for each, setting up shared directories with proper permissions, and generating a summary report. Show the full script.

Answer — Complete automation script:

#!/bin/bash # ============================================ # Linux Server Setup Script for Small Company # ============================================ echo "============================================" echo " Company Server Setup Script" echo "============================================" # Step 1: Create departments (groups) echo "" echo "[1/5] Creating department groups..." for dept in HR IT Sales; do sudo groupadd "$dept" 2>/dev/null echo " ✅ Group: $dept" done # Step 2: Create users for each department echo "" echo "[2/5] Creating users..." declare -A users=( ["hr_anna"]="HR" ["hr_bob"]="HR" ["it_charlie"]="IT" ["it_diana"]="IT" ["sales_eve"]="Sales" ["sales_frank"]="Sales" ) for user in "${!users[@]}"; do dept="${users[$user]}" sudo useradd -m -g "$dept" -s /bin/bash "$user" 2>/dev/null echo " ✅ User: $user (Department: $dept)" done # Step 3: Create shared directories echo "" echo "[3/5] Creating shared directories..." for dept in HR IT Sales; do sudo mkdir -p "/shared/$dept" sudo chown "root:$dept" "/shared/$dept" sudo chmod 2770 "/shared/$dept" # SetGID + owner/group rwx echo " ✅ /shared/$dept (SetGID, group: $dept)" done # Step 4: Set ACLs for cross-department access echo "" echo "[4/5] Setting cross-department ACLs..." # Allow IT to read all departments sudo setfacl -R -m g:IT:rx /shared/ echo " ✅ IT department can read all shared directories" # Step 5: Generate summary report echo "" echo "[5/5] Generating report..." REPORT="/tmp/setup_report.txt" echo "=== SERVER SETUP REPORT ===" > "$REPORT" echo "Date: $(date)" >> "$REPORT" echo "" >> "$REPORT" echo "--- Groups ---" >> "$REPORT" for dept in HR IT Sales; do getent group "$dept" >> "$REPORT" done echo "" >> "$REPORT" echo "--- Users ---" >> "$REPORT" for user in "${!users[@]}"; do id "$user" >> "$REPORT" 2>/dev/null done echo "" >> "$REPORT" echo "--- Shared Directories ---" >> "$REPORT" ls -la /shared/*/ >> "$REPORT" 2>/dev/null echo "" >> "$REPORT" echo "--- ACLs ---" >> "$REPORT" getfacl /shared/HR >> "$REPORT" 2>/dev/null echo "" echo "============================================" echo " ✅ SETUP COMPLETE!" echo " 📄 Report saved to: $REPORT" echo "============================================"
This script demonstrates: for loops, associative arrays, user/group management, permissions, SetGID, ACLs, output redirection, and report generation — all key exam topics!
