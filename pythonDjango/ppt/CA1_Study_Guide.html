📚 Django Basics - Simple Language Guide

This section covers everything you need to know before solving any CA1 set. Read this carefully — every question uses these concepts.

1. What is Django?

Django is a Python web framework that helps you build websites quickly. Think of it as a toolbox that already has many tools ready for you — you just need to learn how to use them.

Key Point: Django follows the MVT (Model-View-Template) pattern. For CA1, we only need Views and Templates.

2. Project Structure

When you create a Django project, this is how it looks:

myproject/ ├── myproject/ ← Main project settings folder │ ├── settings.py ← Project settings (don't change much) │ ├── urls.py ← Main URL routing (connects URLs to views) │ └── wsgi.py ├── myapp/ ← Your app folder (where YOU write code) │ ├── views.py ← YOUR LOGIC goes here (the brain) │ ├── urls.py ← YOUR URL patterns go here │ └── templates/ ← YOUR HTML files go here │ └── result.html ← The page that shows results └── manage.py ← Django command tool

3. URLs (The Address System)

Just like your house has an address, every page on a website has a URL. Django needs to know: "When someone visits this URL, which function should run?"

Simple URL Pattern:

# myapp/urls.py from django.urls import re_path from . import views urlpatterns = [ # When someone visits /hello/, run views.hello function re_path(r'^hello/$', views.hello), ]

URL with Parameters (Named Groups):

This is what ALL CA1 questions use. Named parameters let you capture values from the URL.

# URL pattern with named parameters using regex re_path(r'^process/(?P<type>\w+)/(?P<value>\w+)/$', views.process_view) # Breakdown: # /process/ → literal text, must match exactly # (?P<type>\w+) → captures a word and stores it as 'type' # / → literal slash # (?P<value>\w+) → captures a word and stores it as 'value' # / → literal slash at end
💡 Simple Trick: (?P<name>...) means "grab whatever matches here and call it 'name'". You use it in your view like a variable.

Regex Patterns You Must Know:

PatternMeaningExample Match
\w+One or more letters/numbershello, 123, abc
\d+One or more digits only123, 45
\d{4}Exactly 4 digits1234 (not 12 or 12345)
\d{5}Exactly 5 digits12345
[0-9]Same as \d, one digit0-9
[a-zA-Z]+Only letters (no numbers)hello

4. Views (The Brain / Logic)

The view is a Python function that receives the request, does all the calculations, and sends back a response. This is where ALL your logic goes.

# myapp/views.py from django.shortcuts import render # This is a view function # 'request' is always the first parameter # 'type' and 'value' come from the URL (?P<type> and ?P<value>) def process_view(request, type, value): # Do your Python logic here result = "Something" # Pass results to the HTML template context = { 'result': result, } # Render the template with the data return render(request, 'result.html', context)
💡 Key Points:
  • request is always the FIRST parameter
  • Other parameters must match the named groups in your URL pattern exactly
  • render(request, 'file.html', context) sends data to your HTML page
  • context is a dictionary — keys become variable names in HTML

GET vs POST (Used in Set C and Set I):

def my_view(request, ...): if request.method == 'GET': # User is just visiting the page / loading the form return render(request, 'form.html') elif request.method == 'POST': # User submitted the form username = request.POST.get('username') password = request.POST.get('password') # Process the data... return render(request, 'result.html', context)

5. Templates (HTML with Django)

Templates are regular HTML files but with Django template tags that let you display Python data.

<!-- templates/result.html --> <!DOCTYPE html> <html> <head><title>Result</title></head> <body> <h1>Results</h1> <!-- Display a variable from context --> <p>The result is: {{ result }}</p> <!-- Loop through a list --> {% for item in items %} <p>{{ item }}</p> {% endfor %} <!-- If condition --> {% if status == "pass" %} <p style="color:green">PASS</p> {% else %} <p style="color:red">FAIL</p> {% endif %} </body> </html>
💡 Remember:
  • {{ variable }} — displays a value (double curly braces)
  • {% for x in list %} ... {% endfor %} — loops through a list
  • {% if condition %} ... {% endif %} — conditional display

6. Connecting Everything (URL → View → Template)

This is the most important concept. Here's the complete flow:

  1. User types URL in browser: /process/number/42/
  2. Django checks urls.py to find a matching pattern
  3. URL pattern r'^process/(?P<type>\w+)/(?P<value>\w+)/$' matches, extracting type="number" and value="42"
  4. Django calls views.process_view(request, type="number", value="42")
  5. The view function runs all the Python logic
  6. The view calls render(request, 'result.html', context)
  7. The HTML template displays the results to the user

Complete Example - urls.py:

# myapp/urls.py from django.urls import re_path from . import views urlpatterns = [ re_path(r'^process/(?P<type>\w+)/(?P<value>\w+)/$', views.process_view), ]

Complete Example - views.py:

from django.shortcuts import render def process_view(request, type, value): # Your logic here context = {'type': type, 'value': value} return render(request, 'result.html', context)

Complete Example - result.html:

<!DOCTYPE html> <html> <body> <h1>Type: {{ type }}, Value: {{ value }}</h1> </body> </html>

  • max() — use loops to find maximum manually

  • External libraries — only use Django and Python built-ins
✅ How to count without Counter:
# Instead of Counter(list), use this: counts = {} for item in my_list: if item in counts: counts[item] += 1 else: counts[item] = 1 # counts = {1: 3, 2: 2, 3: 3, 4: 2, 5: 1}
✅ How to find max without max():
# Instead of max(list), use this: maximum = my_list[0] # assume first is max for item in my_list: if item > maximum: maximum = item # maximum now holds the largest value
✅ How to sort without sort()/sorted():
# Bubble sort - simple and always works lst = list(my_tuple) # convert tuple to list first for i in range(len(lst)): for j in range(len(lst) - 1): if lst[j] > lst[j + 1]: lst[j], lst[j + 1] = lst[j + 1], lst[j]

📝 SET A - Process Number/Text + Top-K Frequency

URL Pattern: /process/<type>/<value>/ | Marks: 30

📋 What This Question Asks

Two tasks in one view:

  1. Number type: Check if positive/negative/zero AND even/odd
  2. Text type: Count characters and vowels
  3. Always (both types): Find top-K most frequent elements from tuple (1,1,1,2,2,3,3,3,4,4,5) with K=2
  4. Invalid type: Show error message
🚫 Restrictions: Cannot use Counter, sort(), sorted()

🔗 urls.py

from django.urls import re_path from . import views urlpatterns = [ re_path(r'^process/(?P<type>\w+)/(?P<value>\w+)/$', views.process_view), ]

🧠 views.py

from django.shortcuts import render def process_view(request, type, value): context = {'type': type, 'value': value} # ---- TASK 1: Top-K Frequency (always runs) ---- data = (1, 1, 1, 2, 2, 3, 3, 3, 4, 4, 5) K = 2 # Count frequency using dictionary (no Counter!) freq = {} for num in data: if num in freq: freq[num] += 1 else: freq[num] = 1 # Find top K elements manually (no sort!) top_k = [] freq_copy = dict(freq) # work on a copy for _ in range(K): # Find element with highest frequency max_count = 0 max_element = 0 for key in freq_copy: if freq_copy[key] > max_count: max_count = freq_copy[key] max_element = key top_k.append((max_element, max_count)) del freq_copy[max_element] context['freq'] = freq context['top_k'] = top_k context['K'] = K # ---- Check type and process ---- if type == 'number': # Check if value is a valid number if value.lstrip('-').isdigit(): num = int(value) # Positive / Negative / Zero if num > 0: context['sign'] = 'Positive' elif num < 0: context['sign'] = 'Negative' else: context['sign'] = 'Zero' # Even / Odd if num % 2 == 0: context['parity'] = 'Even' else: context['parity'] = 'Odd' context['valid'] = True else: context['error'] = 'Invalid number value!' elif type == 'text': # Count characters and vowels char_count = len(value) vowels = 'aeiouAEIOU' vowel_count = 0 for ch in value: if ch in vowels: vowel_count += 1 context['char_count'] = char_count context['vowel_count'] = vowel_count context['valid'] = True else: context['error'] = 'Invalid type! Use "number" or "text".' return render(request, 'result.html', context)

📄 templates/result.html

<!DOCTYPE html> <html> <head><title>Process Result</title></head> <body> <h1>Processing: {{ type }} = {{ value }}</h1> {% if error %} <p style="color:red">{{ error }}</p> {% endif %} {% if valid %} {% if type == "number" %} <p>Sign: {{ sign }}</p> <p>Parity: {{ parity }}</p> {% endif %} {% if type == "text" %} <p>Character Count: {{ char_count }}</p> <p>Vowel Count: {{ vowel_count }}</p> {% endif %} {% endif %} <hr> <h2>Top {{ K }} Most Frequent Elements</h2> <p>Full Frequency: {{ freq }}</p> {% for item, count in top_k %} <p>Element: {{ item }}, Frequency: {{ count }}</p> {% endfor %} </body> </html>

🎤 Viva Questions for Set A

Q: What does (?P<type>\w+) mean in the URL pattern?
It captures one or more word characters from the URL and stores them in a variable called 'type'. The \w+ means letters, digits, or underscore. (?P<name>...) is a named group in regular expression.
Q: How did you find Top-K without using sort() or Counter?
First, I used a dictionary to count frequencies by looping through the tuple. Then, to find top-K, I looped K times, each time finding the element with the highest frequency using a simple comparison loop, then removed it and repeated.
Q: What is the difference between render() and HttpResponse()?
render() takes a template (HTML file) and data (context dictionary) and returns a complete page. HttpResponse() just returns raw text/HTML directly. render() is preferred because it separates logic from presentation.
Q: What is the output for /process/number/0/?
Sign: Zero, Parity: Even. Because 0 is neither positive nor negative, and 0 % 2 == 0 makes it even.
Q: What happens if someone visits /process/random/abc/?
The type 'random' doesn't match 'number' or 'text', so the error message 'Invalid type! Use "number" or "text".' is displayed.

📝 SET B - Electricity Bill + Zero-Sum Subarrays

URL Pattern: /bill/<customer_id>/<units>/ | Marks: 30

📋 What This Question Asks

  1. Electricity Bill: Calculate bill based on unit ranges (if-elif-else)
  2. Zero-Sum Subarrays: From tuple (1, -1, 2, -2), find all contiguous subarrays that sum to zero
  3. Validation: customer_id must be valid, units must not be negative

🔗 urls.py

from django.urls import re_path from . import views urlpatterns = [ re_path(r'^bill/(?P<customer_id>\w+)/(?P<units>\d+)/$', views.bill_view), ]

🧠 views.py

from django.shortcuts import render def bill_view(request, customer_id, units): context = {'customer_id': customer_id, 'units': units} # ---- Validate customer_id ---- if not customer_id.isdigit(): context['error'] = 'Invalid customer ID! Must be digits only.' return render(request, 'bill.html', context) units = int(units) # ---- Validate units ---- if units < 0: context['error'] = 'Invalid units! Cannot be negative.' return render(request, 'bill.html', context) # ---- Electricity Bill Calculation ---- if units <= 100: rate = 1.5 elif units <= 200: rate = 2.5 elif units <= 300: rate = 3.5 else: rate = 4.5 bill_amount = units * rate context['rate'] = rate context['bill_amount'] = bill_amount # ---- Zero-Sum Subarrays ---- data = (1, -1, 2, -2) subarrays = [] # Check every possible contiguous subarray for i in range(len(data)): current_sum = 0 for j in range(i, len(data)): current_sum += data[j] if current_sum == 0: # Extract subarray from index i to j sub = [] for k in range(i, j + 1): sub.append(data[k]) subarrays.append(sub) context['subarrays'] = subarrays context['total_count'] = len(subarrays) return render(request, 'bill.html', context)

📄 templates/bill.html

<!DOCTYPE html> <html> <head><title>Bill Result</title></head> <body> <h1>Electricity Bill - Customer: {{ customer_id }}</h1> {% if error %} <p style="color:red">{{ error }}</p> {% else %} <p>Units Consumed: {{ units }}</p> <p>Applicable Rate: {{ rate }} per unit</p> <p>Bill Amount: {{ bill_amount }}</p> <hr> <h2>Zero-Sum Subarrays from (1, -1, 2, -2)</h2> {% for sub in subarrays %} <p>{{ sub }}</p> {% endfor %} <p>Total Zero-Sum Subarrays: {{ total_count }}</p> {% endif %} </body> </html>

🎤 Viva Questions for Set B

Q: How do you find all contiguous subarrays?
Use nested loops. The outer loop (i) picks the starting index, and the inner loop (j) picks the ending index. For each pair (i,j), we sum elements from i to j. If sum is zero, we record that subarray.
Q: What is a contiguous subarray?
A contiguous subarray means elements that are next to each other in the original tuple, in order. For (1,-1,2,-2), [1,-1] is contiguous, but [1,2] is NOT because -1 is skipped.
Q: What are the zero-sum subarrays for (1, -1, 2, -2)?
[1, -1], [1, -1, 2, -2], [-1, 2, -1]... Let me calculate: Starting from index 0: [1,-1]=0 ✓, [1,-1,2,-2]=0 ✓. From index 1: [-1,2,-1]=0? No, that's [−1,2]=1. Actually [−1,2,−2]=−1. From index 2: [2,−2]=0 ✓. So the zero-sum subarrays are [1,-1], [2,-2], and [1,-1,2,-2] — total 3.
Q: Why use if-elif-else for electricity bill?
Because the rate depends on which range the units fall into. We check ranges in order: first 0-100, then 101-200, etc. Using elif means once a condition is true, the rest are skipped automatically.

📝 SET C - Student GET/POST + Employee Highest Paid

URL Pattern: /student/<roll_no>/ | Marks: 30

📋 What This Question Asks

  1. GET request: Show a form to enter marks
  2. POST request: Process marks → determine Pass/Fail (marks >= 40 to pass)
  3. Employee Analysis: From employee records, find highest-paid employee in each department (NO max() allowed)
Employee Records: (Use a tuple of dictionaries)
employees = ( {'name': 'Alice', 'dept': 'IT', 'salary': 75000}, {'name': 'Bob', 'dept': 'HR', 'salary': 50000}, {'name': 'Charlie', 'dept': 'IT', 'salary': 90000}, {'name': 'Diana', 'dept': 'HR', 'salary': 60000}, {'name': 'Eve', 'dept': 'Finance', 'salary': 80000}, {'name': 'Frank', 'dept': 'Finance', 'salary': 70000}, )

🔗 urls.py

from django.urls import re_path from . import views urlpatterns = [ # roll_no must be exactly 4 digits re_path(r'^student/(?P<roll_no>\d{4})/$', views.student_view), ]

from django.shortcuts import render def student_view(request, roll_no): context = {'roll_no': roll_no} # ---- Employee Analysis (always runs) ---- employees = ( {'name': 'Alice', 'dept': 'IT', 'salary': 75000}, {'name': 'Bob', 'dept': 'HR', 'salary': 50000}, {'name': 'Charlie', 'dept': 'IT', 'salary': 90000}, {'name': 'Diana', 'dept': 'HR', 'salary': 60000}, {'name': 'Eve', 'dept': 'Finance', 'salary': 80000}, {'name': 'Frank', 'dept': 'Finance', 'salary': 70000}, ) # Group employees by department using dictionary dept_groups = {} for emp in employees: dept = emp['dept'] if dept not in dept_groups: dept_groups[dept] = [] dept_groups[dept].append(emp) # Find highest paid in each department (no max()!) highest_paid = {} for dept in dept_groups: top_emp = dept_groups[dept][0] for emp in dept_groups[dept]: if emp['salary'] > top_emp['salary']: top_emp = emp highest_paid[dept] = top_emp context['highest_paid'] = highest_paid # ---- Handle GET and POST ---- if request.method == 'GET': context['show_form'] = True elif request.method == 'POST': marks = request.POST.get('marks', '') if marks.isdigit(): marks = int(marks) context['marks'] = marks if marks >= 40: context['result'] = 'Pass' else: context['result'] = 'Fail' else: context['error'] = 'Invalid marks! Please enter a number.' return render(request, 'student.html', context)

🎤 Viva Questions for Set C

Q: What is the difference between GET and POST?
GET is used when the user is just viewing/loading a page. Data is in the URL. POST is used when the user submits form data. Data is in the request body, which is more secure for sensitive info.
Q: What does {% csrf_token %} do?
CSRF stands for Cross-Site Request Forgery. {% csrf_token %} adds a hidden security token to the form to prevent attacks where a malicious site submits forms on behalf of the user. Django requires it for POST forms.
Q: How did you find highest-paid without max()?
I assumed the first employee is the highest, then looped through all employees. If any employee has a higher salary, I replaced my assumption. At the end of the loop, I have the highest.
Q: What does request.POST.get('marks', '') do?
It retrieves the value of the 'marks' field from the submitted POST form. The second parameter '' is a default value — if 'marks' is not found, it returns an empty string instead of None.

📝 SET D - Date Validation + Anagram Grouping

URL Pattern: /date/<day>/<month>/<year>/ | Marks: 30

📋 What This Question Asks

  1. Date Validation: Check if the date is valid (day/month/year ranges)
  2. Anagram Grouping: Group words from tuple that are anagrams using character-frequency signature (NO sorted()!)

🔗 urls.py

from django.urls import re_path from . import views urlpatterns = [ re_path(r'^date/(?P<day>\d{1,2})/(?P<month>\d{1,2})/(?P<year>\d{4})/$', views.date_view), ]

🧠 views.py

from django.shortcuts import render def date_view(request, day, month, year): context = {'day': day, 'month': month, 'year': year} # ---- Task 1: Date Validation ---- day = int(day) month = int(month) year = int(year) valid = True if year < 1: valid = False elif month < 1 or month > 12: valid = False else: # Days in each month days_in_month = (31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31) # Simple leap year check if month == 2 and (year % 4 == 0): max_days = 29 else: max_days = days_in_month[month - 1] if day < 1 or day > max_days: valid = False context['valid'] = valid # ---- Task 2: Anagram Grouping ---- words = ("eat", "tea", "tan", "ate", "nat", "bat") # Create a character frequency signature for each word # Two words are anagrams if they have the same signature anagram_groups = {} for word in words: # Build frequency signature (cannot use sorted!) freq = [0] * 26 # 26 letters for ch in word: freq[ord(ch) - ord('a')] += 1 # Convert to tuple so it can be a dictionary key signature = tuple(freq) # Group words with same signature if signature not in anagram_groups: anagram_groups[signature] = [] anagram_groups[signature].append(word) # Convert dictionary values to a list for display groups = list(anagram_groups.values()) context['anagram_groups'] = groups return render(request, 'date.html', context)

📄 templates/date.html

<!DOCTYPE html> <html> <head><title>Date & Anagram Result</title></head> <body> <h1>Date: {{ day }}/{{ month }}/{{ year }}</h1> <p>Date is: {% if valid %}Valid{% else %}Invalid{% endif %}</p> <hr> <h2>Anagram Groups</h2> {% for group in anagram_groups %} <p>{{ group }}</p> {% endfor %} </body> </html>

🎤 Viva Questions for Set D

Q: What is an anagram?
Two words are anagrams if they contain exactly the same characters with the same frequencies, but in different order. For example, "eat" and "tea" both have one 'e', one 'a', one 't'.
Q: How did you group anagrams without sorted()?
Instead of sorting each word's characters, I created a character frequency signature — a list of 26 counts (one for each letter). Two words with the same frequency signature are anagrams. I used this signature as a dictionary key to group them.
Q: What does ord('a') return?
ord() returns the ASCII/Unicode code of a character. ord('a') returns 97. So ord(ch) - ord('a') gives us 0 for 'a', 1 for 'b', ..., 25 for 'z' — perfect for indexing into our 26-element list.
Q: What is the anagram grouping output?
Group 1: ["eat", "tea", "ate"] — all have {a:1, e:1, t:1}. Group 2: ["tan", "nat"] — both have {a:1, n:1, t:1}. Group 3: ["bat"] — alone with {a:1, b:1, t:1}.

📝 SET E - Employee Salary + Transaction Fraud Detector

URL Pattern: /employee/<emp_id>/<salary>/ | Marks: 30

📋 What This Question Asks

  1. Salary Calculator: emp_id must be exactly 5 digits, salary must be digits only. Classify employee category and calculate bonus
  2. Fraud Detector: Group transactions by account, find suspicious accounts (total > limit AND count > min_transactions)

🔗 urls.py

from django.urls import re_path from . import views urlpatterns = [ re_path(r'^employee/(?P<emp_id>\d{5})/(?P<salary>\d+)/$', views.employee_view), ]

🧠 views.py

from django.shortcuts import render def employee_view(request, emp_id, salary): context = {'emp_id': emp_id, 'salary': salary} salary = int(salary) # ---- Task 1: Employee Salary Classification ---- if salary < 30000: category = 'Junior' bonus = salary * 0.10 elif salary < 60000: category = 'Mid-Level' bonus = salary * 0.15 elif salary < 100000: category = 'Senior' bonus = salary * 0.20 else: category = 'Executive' bonus = salary * 0.25 total = salary + bonus context['category'] = category context['bonus'] = bonus context['total'] = total # ---- Task 2: Transaction Fraud Detector ---- transactions = ( {'account': 'A1', 'amount': 5000}, {'account': 'A1', 'amount': 3000}, {'account': 'A2', 'amount': 1000}, {'account': 'A1', 'amount': 2000}, {'account': 'A2', 'amount': 500}, {'account': 'A3', 'amount': 4000}, ) limit = 8000 min_transactions = 2 # Group by account accounts = {} for t in transactions: acc = t['account'] if acc not in accounts: accounts[acc] = {'total': 0, 'count': 0, 'amounts': []} accounts[acc]['total'] += t['amount'] accounts[acc]['count'] += 1 accounts[acc]['amounts'].append(t['amount']) # Find suspicious accounts suspicious = [] for acc in accounts: info = accounts[acc] if info['total'] > limit and info['count'] > min_transactions: suspicious.append({ 'account': acc, 'total': info['total'], 'count': info['count'], }) context['accounts'] = accounts context['suspicious'] = suspicious context['limit'] = limit context['min_trans'] = min_transactions return render(request, 'employee.html', context)

📄 templates/employee.html

<!DOCTYPE html> <html> <head><title>Employee Result</title></head> <body> <h1>Employee {{ emp_id }} - Salary: {{ salary }}</h1> <p>Category: {{ category }}</p> <p>Bonus: {{ bonus }}</p> <p>Total (Salary + Bonus): {{ total }}</p> <hr> <h2>Transaction Fraud Detector</h2> <p>Limit: {{ limit }}, Min Transactions: {{ min_trans }}</p> <h3>All Accounts:</h3> {% for acc, info in accounts.items %} <p>{{ acc }}: Total={{ info.total }}, Count={{ info.count }}</p> {% endfor %} <h3>Suspicious Accounts:</h3> {% if suspicious %} {% for s in suspicious %} <p style="color:red">{{ s.account }}: Total={{ s.total }}, Count={{ s.count }}</p> {% endfor %} {% else %} <p>No suspicious accounts found.</p> {% endif %} </body> </html>

🎤 Viva Questions for Set E

Q: What are the two fraud conditions?
An account is suspicious if: (1) total transaction amount exceeds the limit, AND (2) the account has more than the minimum number of transactions. Both conditions must be true.
Q: How did you group transactions by account?
I used a dictionary where keys are account IDs and values contain total amount, count, and individual amounts. For each transaction, I checked if the account existed in the dictionary; if not, I created a new entry. Then I updated the total and count.

🎤 Viva Questions for Set I

Q: What is a majority element?
A majority element is an element that appears more than n/2 times in the tuple, where n is the total number of elements. For (2,2,1,1,1,2,2), n=7, so majority requires more than 3 appearances. Element 2 appears 4 times, so it IS the majority.
Q: How does the Boyer-Moore voting algorithm work?
Start with count=0 and no candidate. For each element: if count is 0, make it the candidate. If element matches candidate, increment count. If not, decrement count. The surviving candidate is then verified by counting its actual frequency.
Q: Why do we need to verify the candidate?
The voting algorithm only finds a possible candidate. It doesn't guarantee the candidate is actually a majority. For example, in (1, 2, 3), the algorithm might pick 3 as candidate, but no element appears more than 1 time. So we must count its frequency and check if it's really > n/2.
Q: What happens if no majority exists?
We display 'No Majority Element'. This is handled by checking if the frequency of our candidate is greater than n//2. If not, there's no majority element in the tuple.

Django Core Concepts

Q: What is Django and why use it?
Django is a Python web framework that follows the MVT (Model-View-Template) pattern. It provides tools for URL routing, database management, form handling, and HTML templates, making web development faster and more organized.
Q: What is the MVT pattern?
MVT stands for Model-View-Template. Model handles data/database, View handles logic/processing, and Template handles the HTML display. For CA1, we primarily work with Views and Templates.
Q: What does re_path() do vs path()?
re_path() uses regular expressions for URL matching, giving us more control (like \d{4} for exactly 4 digits). path() uses simpler converters like <int:id>. We use re_path() in CA1 for more precise URL validation.
Q: What is the difference between a URL pattern and a URL parameter?
A URL pattern is the full route definition like r'^student/(?P<roll_no>\d{4})/$'. Named URL parameters (like (?P<roll_no>\d{4})) are parts of the URL that are captured and passed as arguments to the view function.
Q: How does Django match a URL to a view?
Django checks each URL pattern in urlpatterns in order. The first pattern that matches the requested URL is used. Named groups (?P<name>...) capture values and pass them as keyword arguments to the view function.

Python Concepts Used in All Sets

Q: What is a dictionary in Python?
A dictionary stores key-value pairs. Keys are unique. Example: {'IT': 75000, 'HR': 50000}. We use it for counting frequencies, grouping data, and existence checking in CA1.
Q: What is a tuple vs list?
A tuple is immutable (cannot be changed after creation) and uses parentheses (1,2,3). A list is mutable and uses square brackets [1,2,3]. We convert tuples to lists when we need to modify them.
Q: How do you check if a key exists in a dictionary?
Using the 'in' keyword: if key in dictionary. This is O(1) — very fast. We use this for frequency checking and existence checking throughout CA1.
Q: What is string slicing?
Slicing extracts parts of a string. s[start:end] gets characters from start index to end-1. Example: "hello"[1:3] returns "el". We use this in date validation and string processing.
Q: What is the difference between == and 'in'?
== checks if two values are equal. 'in' checks if a value exists within a collection (list, dictionary, string). Example: 3 in [1,2,3] returns True; 4 == [1,2,3] would raise an error.

Algorithm Concepts

Q: What is a subarray vs sublist?
A subarray (or subsequence in this context) must be contiguous — elements must be next to each other in the original. [1,2] is a subarray of [1,2,3] but [1,3] is not because 2 is skipped.
Q: What is the difference between O(n) and O(n²)?
O(n) means the algorithm runs in proportion to the input size — linear time. O(n²) means it takes n × n operations — much slower. For example, nested loops for finding all subarrays is O(n²).
Q: What is Boyer-Moore Voting Algorithm?
It's an algorithm to find a majority element in O(n) time and O(1) space. It maintains a candidate and a counter. When the counter drops to zero, a new candidate is chosen. After one pass, verify if the candidate is actually a majority.
Q: What is prefix sum?
Prefix sum is a running total. For array [1, 0, 1], prefix sums are [1, 1, 2]. It's used to quickly find the sum of any subarray. If prefix_sum[i] == prefix_sum[j], then the subarray from i+1 to j has sum 0.
Q: Why do we use a dictionary for O(1) lookup?
Dictionary lookups are O(1) on average — constant time. Searching in a list is O(n). When we need to frequently check if a value exists, dictionaries are much faster. This is why we use them for existence checking instead of scanning through the tuple each time.

HTTP Concepts

Q: What is GET and when to use it?
GET is an HTTP method used to retrieve/requests data. The data is passed in the URL as query parameters. We use it for loading pages and displaying forms. It's not secure for sensitive data because data is visible in the URL.
Q: What is POST and when to use it?
POST is an HTTP method used to send/submit data to the server. Data is in the request body, not visible in the URL. We use it for form submissions, login forms, and any action that modifies data.
Q: What does {% csrf_token %} do?
It generates a hidden field with a security token that Django validates on POST requests. This prevents Cross-Site Request Forgery attacks where a malicious website submits forms on behalf of your user.
